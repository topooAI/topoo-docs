## Purpose
This document defines the role of Linear inside the `toProject` architecture.

## Block Position
Inside the `toProject` board, this page belongs to the `Boundary & Version Strategy` block.

## Core Position
Linear is the `human execution queue`.

Linear owns:
- issue state
- assignee flow
- priority
- cycle planning
- project-level backlog discipline
- team operational hygiene

Linear does not own:
- project semantic model
- run ledger
- runtime truth
- execution traces
- artifact evidence

## Why Linear Is Not Enough
Linear is excellent at managing human work flow.

It is not built to govern:
- agent runs
- runtime posture
- execution evidence
- source/runtime/artifact version linkage

That is why `toProject` must exist.

The key issue is that Linear remains a human task management system.

It can represent:
- issue progress
- owner
- priority
- planning cadence

It cannot become the semantic center of:
- git-backed execution state
- runtime-aware work
- run / activity / artifact lineage
- agent operating posture

Once the execution subject becomes `human + agent`, the underlying structure is no longer a normal issue tracker.

That is why both the data model and the interface have to change.

## Boundary
Linear should remain the best place for team-level issue discipline.

`toProject` should remain the place where human and agent execution become one readable project system.
