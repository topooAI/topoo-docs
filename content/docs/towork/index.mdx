`toWork` is the board for document work, authored artifacts, and publishable outputs inside Topoo.

It exists to answer how content is created, structured, edited, reviewed, and published once conversation or project work needs to become a durable artifact.

## What this board owns

This board should define:

- document surface behavior
- editing and reading modes
- content block rules
- publishing structure
- artifact lifecycle
- acceptance criteria for document quality and delivery

The board should answer:

> how does work become a stable artifact inside Topoo?

## Core thesis

`toWork` is not just a text editor.

It is the lane where transient thinking becomes:

- a readable document
- a structured artifact
- a shareable output
- a published or reviewable surface

This means the board must hold both interface rules and content contracts.

## Major topics that belong here

This board should expand into pages such as:

- document information architecture
- editing flows and document modes
- block primitives and content composition
- publish and preview behavior
- acceptance checklists for final artifacts
- work artifact states: draft, review, publish

## Relationship to other boards

- `toAgent` may generate or assist work artifacts, but it does not own the artifact surface.
- `toProject` may organize work into a project container, but it does not own document publishing behavior.
- `toMemory` may retain supporting context, but it does not own authored document form.
- `TopooUI` owns shared document UI primitives and documentation display patterns.

## Current direction

The `toWork` board should move toward:

- explicit document states
- stable content structure
- low-friction editing
- predictable publish paths
- reusable document patterns across the product

It should become the source of truth for work artifacts, not a loose collection of pages about writing.
