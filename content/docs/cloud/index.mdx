Topoo Cloud turns distributed serverless infrastructure into a customer-facing private cloud with concrete projects, nodes, resources, deployments, and operating state.

Customers buy and operate Topoo capacity. They should not need to understand which upstream provider implements a runtime, database, storage service, network, or security capability.

## Core terms

| Term | Meaning |
|---|---|
| Workspace | The tenant and policy boundary that owns projects, members, plans, and shared capacity. |
| Cloud Project | The externally unified product and release subject that organizes Nodes, environments, resources, domains, deployments, and observability. |
| Node | A persistent, permission-scoped code container and attention boundary inside a Project. |
| Node Workbench | The common editing and lifecycle surface for a Node; specialized visual and no-code editors operate on the same canonical Source. |
| Agent | An actor that works under a Node's scope, identity, permissions, and operating procedure. |
| Session | A temporary execution context attached to a Node; it does not define a new responsibility boundary. |
| Submission | A bounded proposed change from a person, Agent, or Session; it does not carry Production authority. |
| Source Revision | One immutable canonical Source state, represented by a Git commit, imported snapshot, or Topoo-hosted commit. |
| Node Version | An immutable accepted Node state that pins Source, Submissions, Checks, dependencies, and delivery metadata. |
| Artifact | An immutable build output produced from an exact Node Version and build contract. |
| Resource | A project-bound capability such as a database, object store, queue, domain, secret, or AI service. |
| Project Release | The accepted, immutable set of Node versions that represents the product. |
| Deployment | Binding and promotion of an accepted Project Release Artifact Set into an Environment, linked back to Node Versions, Source Revisions, Checks, and approvals. |

## Product rule

Topoo Cloud is the customer-facing abstraction.

Upstream providers are implementation details. Product language, quotas, status, billing, and documentation must describe Topoo capabilities first.

Provider-specific identifiers may exist in internal adapters and diagnostics, but they must not define the customer model.

## Relationship to toProject

`toProject` documents the project object for agent-led work and execution.

Topoo Cloud documents the infrastructure control plane used to run and expose software. A Cloud Project may host or deploy outputs produced by `toProject`, but the two concepts have different responsibilities and must not be collapsed into one model.
