This page records the implementation state observed on **July 27, 2026**.

Status is binary:

- **Completed** — the full user outcome has been verified
- **Not completed** — at least one required part is missing or has not been accepted

Existing components inside a not-completed capability are listed as evidence. They do not change the final status.

## Completed

| Capability | Current evidence |
|---|---|
| Project repository binding | Projects persist provider, repository, branch, sync mode, status, and provider metadata. |
| Repository sync records | Sync attempts and their status are persisted per repository link. |
| GitHub App integration surface | App configuration, installation callback, installation repository listing, and signed webhook endpoints exist. |
| GitHub source reads | Topoo can resolve repository branches and commits, read repository trees, and import an immutable commit archive. |
| Node source browser | The Node editor can display the repository tree, branch, files, text previews, and derived source structure. |
| Change Request model | GitHub Pull Requests are normalized into Node Change Requests. |
| Check model | GitHub Check Runs are normalized and attached to Change Requests. |
| Immutable source snapshot | Deployments can resolve and retain a source snapshot tied to a specific commit or uploaded manifest. |
| Deployment ledger | Deployment records preserve source identity, status, target, and artifact information. |
| Exact-revision redeploy path | A recorded GitHub commit or Topoo upload manifest can be selected as the deployment source. |

## Current product boundary

Topoo Cloud currently has a substantial **GitHub-connected source and deployment control-plane foundation**.

It does not yet have a complete **Topoo-native Git collaboration platform** or the final **Agent Release Controller**.

The next implementation milestone should not be another isolated deployment button. It should establish the canonical Agent Submission and Release Candidate objects, then connect them to the existing repository, Change Request, Check, source snapshot, and deployment records.

## Live verification boundary

The authenticated production control plane was also inspected during this audit.

- the Dashboard loaded with the active workspace and real operating data
- the Projects page showed the live Topoo Cloud project and a completed local-source import
- the Project Code view displayed the active branch and a browsable repository tree

This verifies the deployed project/source browsing path.

It does **not** verify GitHub App onboarding, webhook delivery, Topoo-native Git operations, multi-Agent integration, or production release-channel enforcement. Those capabilities remain classified from their current executable code and acceptance evidence, not inferred from the visible Code view.

## Acceptance criteria for the next milestone

The next milestone is complete only when:

1. two Agents can submit independent changes against a pinned base revision
2. the controller detects a stale base or overlapping file ownership
3. accepted changes produce one release candidate
4. required checks run against that integrated candidate
5. preview uses the candidate's immutable artifact
6. production promotion reuses the accepted artifact
7. the UI shows submitter, revisions, checks, approvals, artifact, environments, and rollback
8. one Agent cannot overwrite another Agent's accepted production state
