This page records the implementation state re-audited on **July 29, 2026**.

Status is binary:

- **Completed** — the full user outcome has been verified
- **Not completed** — at least one required part is missing or has not been accepted

Existing components inside a not-completed capability are listed as evidence. They do not change the final status.

## Current product boundary

Topoo Cloud currently has a substantial **GitHub-connected source and deployment control-plane foundation**, plus a first production-backed path from immutable Node Preview to persistent Project Submission.

The following real segment is now available:

```text
immutable Node Revision
→ full-Project Node Preview
→ immutable Artifact
→ approve or reject
→ persistent Project Submission
→ accept or reject record
```

The critical control gap begins after Submission acceptance. Acceptance currently pins the Project's Node reference. It does not yet detect a stale Base Revision, combine concurrent accepted changes, publish a distinct Node Version, create a multi-Node Project Release Candidate, run integrated Checks, or seal a Release Artifact Set.

Topoo Cloud does not yet have a complete **Topoo-native Git collaboration platform**, automatic external **Work Session orchestration**, **Topoo Local Runtime**, or the final **Agent Release Controller**.

The next implementation milestone should close that exact gap rather than add another isolated deployment button or confirmation surface.

## Live verification boundary

The authenticated production control plane was also inspected during this audit.

- the Dashboard loaded with the active workspace and real operating data
- the Projects page showed the live Topoo Cloud project and a completed local-source import
- the Project Code view displayed the active branch and a browsable repository tree

The July 28 production verification additionally confirmed:

- a ready immutable Node Project Preview with Base Release and Artifact identity
- approve or reject decision persistence
- automatic creation of a Project-scoped Submission after Preview approval
- Node `View Submission` handoff into the exact Project Submission
- real `Submissions`, `Releases`, and `Deployments` views in the existing Project navigation
- Release and Deployment records remaining available without replacing the existing Project layout

This verifies the deployed project/source browsing path and the first Preview-to-Submission control-plane segment.

It does **not** verify GitHub App onboarding, webhook delivery, Topoo-native Git operations, multi-Agent integration, or production release-channel enforcement. Those capabilities remain classified from their current executable code and acceptance evidence, not inferred from the visible Code view.

## Next milestone

The next milestone is an **ambient automatic-version and integration-controller MVP**.

The intended experience is:

```text
configure GitHub, Topoo Local Runtime, Project, Nodes, Agent, Checks, and release policy once
→ open multiple external Sessions
→ state only the tasks
→ Topoo creates Project-scoped Work Sessions and resolves one or more Node scopes
→ Local Runtime isolates working state and Topoo records meaningful versions automatically
→ clean work integrates and reaches Preview without routine confirmations
→ only conflicts, authority expansion, destructive changes, failed policy gates, or configured Production approval interrupt the user
```

GitHub provides source history and portability in the background. The execution-client adapter connects the conversation. Topoo Local Runtime owns supervised local isolation. Topoo Cloud owns Agent and Work Session identity, automatic Checkpoints and Change Summaries, integration safety, Release composition, Preview, Production, audit, and rollback.

## Acceptance criteria for the next milestone

The next milestone is complete only when:

1. Workspace and Project configuration persist the source connection, Local Runtime connection, Node scopes, Agent identity, Checks, and release policy once.
2. two external Sessions can work concurrently under the same Project and Node without sharing mutable working state
3. one coherent Work Session can hold several authorized Node scopes and produce separate Node-scoped Submissions
4. Topoo automatically records Drafts, recoverable Checkpoints, source Revisions, and Change Summaries without requiring routine Git confirmation
5. each Node Submission is bound to an Agent, Work Session, Node, and pinned Base Revision
6. the controller detects a stale base or overlapping file and Resource ownership
7. clean independent changes integrate automatically while an unresolved semantic conflict becomes one clear exception
8. accepted changes produce immutable Node Versions that retain both concurrent Sessions' accepted work
9. exact Node Versions, including unchanged retained versions, form one Project Release Candidate
10. required Checks run against that integrated candidate
11. Preview uses the candidate's immutable Release Artifact Set
12. Production promotion reuses the accepted Release Artifact Set under the configured approval policy
13. Node Workbench shows linked Session, submitter, Base Revision, Diff, Change Summary, Checks, Node Version, Artifact, and consuming Release
14. Project Deployment shows included Node Versions, approval, Environment, Release Artifact Set, audit chain, and rollback target
15. one Agent cannot overwrite another Agent's accepted Project or Production state
